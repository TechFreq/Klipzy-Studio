# Packaging Klipzy Studio

Klipzy Studio ships as an Electron desktop app that spawns a Python backend
(FastAPI + Whisper + FFmpeg). Packaging bundles the Electron front end and the
Python source, but **not** a Python interpreter. This document explains why and
what the options are.

## What the installers contain

`ui/package.json` → `build.extraResources` copies into the packaged app:

- `server/` — the FastAPI backend and processing pipeline (minus `__pycache__`)
- `main.py` — the backend entry point
- `requirements.txt` — so the runtime dependencies can be installed on first run

Icons: Windows uses `assets/icon.ico`; macOS and Linux are generated by
electron-builder from `assets/icon.png` (512×512). Regenerate both with
`python scripts/make_icon.py` (requires Pillow).

## Why the virtual environment is not bundled

An earlier build copied the whole `.venv` into the installer. That does not work
on other machines: a Python venv is **not relocatable** — `pyvenv.cfg` and the
`Scripts/*.exe` launchers embed absolute paths to the interpreter on the build
machine. The bundled venv also carries torch/CUDA and pulls the installer into
the multi-gigabyte range.

So the venv bundle was removed. At runtime `ui/electron/main.js` → `findPython()`
looks for, in order: a dev `.venv`/`venv` at the repo root, a `venv` under the
packaged resources (for a future self-contained build), then the system
`python` / `python3`.

## Runtime requirement for packaged installs

The packaged app currently needs Python 3.10+ available on the target machine,
with dependencies installed once:

```bash
pip install -r "<app resources>/requirements.txt"
```

The app surfaces a clear message (via the server-status channel) if the backend
cannot start, instead of hanging on a blank screen.

## Toward a fully self-contained installer

To ship without requiring the user to have Python, use one of:

1. **PyInstaller** — freeze `main.py` + `server/` into a single executable and
   point `extraResources` / `findPython()` at that binary. Best for a clean
   one-file install; needs per-OS build runners.
2. **python-build-standalone / embeddable Python** — bundle a relocatable
   interpreter and `pip install` into it during the build, then bundle that.
3. **First-run bootstrap** — on first launch, create a venv under Electron's
   `userData` dir and `pip install -r requirements.txt` into it. Keeps the
   installer small; first launch is slow and needs network access.

Option 1 is the usual choice for a downloadable desktop app.

## Building

```bash
cd ui
npm install
npm run dist:win     # NSIS installer + portable (Windows)
npm run dist:mac     # DMG (macOS)
npm run dist:linux   # AppImage (Linux)
```

Output lands in `ui/dist/`.
